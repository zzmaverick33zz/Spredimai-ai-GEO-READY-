# mixmaster-local

Локальный бесплатный инструмент для продюсера: **вокал + бит + референс → сведение и мастер WAV 24 бит**.
Всё работает на твоём компьютере: без облаков, без API-ключей, без подписок. Интернет нужен один раз, чтобы поставить зависимости.

Стек: [Matchering](https://github.com/sergree/matchering) (мастеринг по референсу), [Pedalboard](https://github.com/spotify/pedalboard) (EQ, компрессоры, реверб, delay, лимитер, сдвиг высоты Rubber Band), librosa (определение нот pYIN и тональности), pyloudnorm (LUFS по ITU-R BS.1770), numpy/scipy/soundfile, Gradio (интерфейс), matplotlib (графики). Лицензия: GPLv3 (см. `LICENSE`).

## Установка и запуск

Нужен **Python 3.10 или новее** (проверено на 3.12 и 3.13; 3.12 — самый надёжный вариант). Если Python нет: [python.org](https://www.python.org/downloads/), версия 3.12; на Windows при установке отметь «Add python.exe to PATH».

| Система | Запуск |
|---|---|
| Windows | двойной клик по `run.bat` |
| macOS | двойной клик по `run.command` (если macOS не даёт открыть: правый клик → «Открыть»; или в Терминале `chmod +x run.command run.sh`) |
| Linux | `./run.sh` |

Первый запуск сам создаёт окружение `.venv` и ставит зависимости (несколько минут). Дальше запуск занимает секунды, интерфейс открывается в браузере: <http://127.0.0.1:7860>. Остановить: закрыть окно терминала (или Ctrl+C).

Ручная установка одной командой, если нужно: `python3.12 -m venv .venv && .venv/bin/pip install -r requirements.txt`, запуск: `.venv/bin/python app.py`.

## Папки

- `references/` — референс-треки (WAV/FLAC, 44.1 или 48 кГц, лучше 16/24 бит, **весь трек целиком**, минимум 10 с, лучше от 30 с). Бери готовые мастера в том звучании, к которому хочешь прийти: тот же жанр, похожий темп и плотность. Не MP3 с YouTube: компрессия портит верх. После добавления файлов нажми «Обновить список».
- `inputs/` — твои вокалы, биты и готовые сведения. Их можно и просто перетащить в окно; папка нужна для выбора из списка (кнопка «Обновить inputs/»).
- `outputs/` — результаты. Каждый запуск в своей папке `ГГГГММДД_ЧЧММСС_имя/`. Исходники никогда не перезаписываются.
- `presets/` — пресеты (JSON). `_base.json` — значения по умолчанию, остальные их переопределяют. Свои пресеты из интерфейса сохраняются как `user_*.json`.

## Режимы

1. **Вокал + бит → мастер.** Анализ → вокальная цепочка → «место под вокал» в бите → баланс → сумма (−3 dBTP запаса) → лёгкая подготовка → Matchering → контроль true peak.
2. **Мастер по референсу.** Готовый трек + референс → подготовка (HPF 25 Гц, шина 1.5:1, запас) → Matchering.
3. **Мастер без референса.** EQ пресета → компрессор → нормализация до целевого LUFS → soft clip + true-peak лимитер, с повторным замером до 6 раз.

4. **Тюн вокала.** Только коррекция нот, на выходе сухой вокал WAV 24 бит для своей DAW. Бит можно добавить, чтобы точнее определить тональность. Есть график нот «до / после».

В режиме 1 есть ещё два блока:

- **Коррекция нот (тюн).** Высота голоса определяется по pYIN, тональность — по биту, а если бита нет — по самому вокалу. Тонику и лад можно задать вручную, «хроматика» означает любые ноты. Сдвиг делает Rubber Band с сохранением формант, поэтому голос не становится «мультяшным». Ползунки:
  - **Скорость**: 100–200 мс звучит естественно (вибрато и подъезды к нотам сохраняются), 0–20 мс даёт жёсткий автотюн-эффект;
  - **Допуск**: ноты, которые ближе к правильной, чем этот порог в центах, не трогаются;
  - **Сила**: какую часть отклонения убирать.

  Тюнится лид и, если отмечено, бэки в той же тональности. Затюненный лид сохраняется отдельным файлом.
- **Бэк-вокал: до 3 дорожек** (дабл, гармония/второй голос, адлибы). Каждая дорожка выравнивается по лиду на ±60 мс по атакам (кроме адлибов) и проходит ту же цепочку, что и лид. Отличия по роли: срез низа выше, де-эссер сильнее, бэк чуть темнее, у гармоний и адлибов больше пространства. Голоса раскладываются по панораме поочерёдно лево/право, поэтому два голоса всегда стоят по разные стороны. Лид остаётся в центре. Группа бэков проходит мягкий компрессор, в ней делается небольшой провал на 3.5 кГц, чтобы слова лида читались. Вся группа ставится на 4 LU тише лида; это регулируется ползунком и параметром `backing.bus_level_lu`. Отдельным файлом сохраняется стем всего вокала.

На выходе: плеер, WAV 24 бит (по желанию ещё 16 бит и MP3 V0), сведение до мастера (в режиме 1), пара **A/B с выровненной громкостью**, таблица замеров (LUFS, true peak, LRA, 7 полос) и график спектра «до / результат / референс».

### Вокальная цепочка (режим 1)

High-pass (из пресета) → адаптивный срез low-mid (PeakFilter) → компрессор (порог из перцентиля огибающей вокала; при сильных пиках перед ним быстрый пик-компрессор) → де-эссер (своя реализация на scipy: полоса 5–9 кГц, огибающая, снижение только этой полосы) → presence (PeakFilter) и air shelf (HighShelfFilter) → reverb (только wet, с предзадержкой 20 мс и фильтрами на возврате) и delay по BPM (1/8 или 1/4, фильтр на возврате).

### Ползунки

| Ползунок | Что делает |
|---|---|
| Вокал над битом, LU | разница integrated LUFS вокала и бита |
| Де-эссер | 0 = выключен (бит-в-бит без изменений), 1 = максимум (до 12 дБ снижения в полосе) |
| Яркость вокала | ± к presence (половина) и air shelf |
| Reverb / Delay | уровень возврата относительно громкости сухого вокала (0.1 ≈ −20 дБ) |
| Место под вокал (duck) | на сколько дБ полоса 1–4 кГц бита приседает под вокал |
| BPM | нужен для delay; пусто или 0 = delay выключен |
| Сдвиг вокала, мс | плюс = вокал позже, минус = раньше |
| Громкость мастера | «как у референса» или «целевой LUFS» |

## Командная строка (пакетная обработка)

```
.venv/bin/python cli.py mix --vocal inputs/v.wav --beat inputs/b.wav --ref references/r.wav --bpm 140 --preset rap_vocal
.venv/bin/python cli.py master --track inputs/mix.wav --ref references/r.wav --lufs -9
.venv/bin/python cli.py master-noref --track inputs/mix.wav --lufs -14 --mp3
```
(на Windows `.venv\Scripts\python cli.py ...`)


## Решения по умолчанию

Записаны здесь, как просил PROMPT.md:

- **Внутренний формат** 44100 Гц float32, файлы с другой частотой ресемплируются при чтении. Принимаются WAV, FLAC, AIFF, MP3, OGG. Больше двух каналов сводятся в стерео.
- **Моно вокал** обрабатывается в моно и дублируется в стерео перед пространством; reverb даёт стерео-хвост.
- **Хвост эффектов**: к вокалу добавляется 2 с под хвост reverb/delay. Бит зацикливается до длины сухого вокала, длинный бит не обрезается.
- **Адаптивный EQ** сравнивает усреднённую спектральную плотность вокала (относительно полосы 0.5–2 кГц) с `target_curve` пресета. Поправка = разница × `strength` (0.5), не больше ±3 дБ сверх значения пресета. Low-mid можно поднять максимум на +1 дБ, срезать до −3 дБ. Вариант «по референсу» берёт presence/air из **всего** микса референса: это приближение, отдельного вокала референса у нас нет.
- **Компрессор**: порог = 55-й перцентиль RMS-огибающей вокала (50 мс). Если пик-фактор больше 12 дБ, сначала включается быстрый компрессор 6:1 (атака 0.5 мс) с порогом на 6 дБ ниже пика.
- **Де-эссер** срабатывает, только если полоса громкая и по своей статистике (70-й перцентиль), и относительно всего сигнала (ближе 6 + 10×сила дБ к общему уровню). Поэтому яркие гласные и чистый вокал не трогаются.
- **Duck бита** работает только в полосе 1–4 кГц (по формуле «сигнал + (g−1)·полоса»): низ и верх бита не меняются, а без вокала бит остаётся бит-в-бит.
- **Сумма** перед мастером выставляется на −3 dBTP (это и есть запас). Затем HPF 25 Гц, шинный компрессор 1.5:1 с порогом по 90-му перцентилю, снова −3 dBTP.
- **Потолок true peak** −1.0 dBTP (`master.true_peak_db`). После Matchering, если пик выше, работает true-peak лимитер Pedalboard (`BrickwallLimiter`), а последняя страховка — простое снижение громкости.
- **Целевой LUFS**: усиление → мягкий клиппер (только пики выше −7.5 dBFS) → true-peak лимитер, затем замер и поправка секущей до 6 итераций. Если цель недостижима без перегруза, интерфейс об этом предупредит.
- **A/B**: обе версии опускаются до громкости более тихой (без усиления, значит без клиппинга). В режиме 1 «до» — это сырая сумма вокала и бита в том же балансе, без обработки.
- **Пресеты** — стартовые значения, на реальном материале их ещё не донастраивали. В `trap_synthwave` и `rap_vocal` громкость по умолчанию «как у референса», в `clean_streaming` цель −14 LUFS.
- **Память**: длинные треки обрабатываются кусками по 20 с. 12-минутный трек в режиме 1 занимал около 4 ГБ RAM на пике (почти всё уходит на сам Matchering) и примерно 3 минуты. Для треков длиннее 10 минут лучше иметь 8 ГБ RAM. Ограничение Matchering в 15 минут поднято.
- **Тюн**: сдвиг высоты не больше ±1 полутона, чтобы ошибки определения нот не уводили голос. Изменение высоты у Rubber Band применяется примерно на 85 мс раньше (замерено), кривая коррекции на это сдвигается. В жёстком режиме очень быстрое вибрато убирается лишь частично: это ограничение плавного сдвига Rubber Band. На 3 минуты вокала тюн занимает около 20–25 секунд. Если тональность определилась с низкой уверенностью, программа это напишет: тогда лучше задать её вручную.
- **Бэки**: выравнивание по времени постоянным сдвигом (не «растягиванием» по словам, как в VocAlign). Если бэк спет сильно не в ритм, его лучше подрезать в DAW.
- **Офлайн**: аналитика Gradio выключена, темы и шрифты берутся системные, ничего не грузится из интернета. Сервер слушает только `127.0.0.1`.
